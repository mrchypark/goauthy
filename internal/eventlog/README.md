# eventlog

## Overview
`eventlog` builds, validates, queries, streams, verifies, and prunes public lifecycle and security event records stored in Rhiza (`event_log` and `event_log_order`). It is intentionally separate from `audit`, keeping its own identifiers, hash-chain integrity, and privacy rules.

## Invariants
- Event IDs are deterministic SHA-256 base64url digests over `"goauthy/eventlog/v1\x00" + operationID + "\x00" + typ` ([events.go:eventID](file:///Users/cypark/Documents/project/goauthy/internal/eventlog/events.go#L109-L112)), and `Event.valid` bounds `Text` to 4096 valid UTF-8 bytes and `IP` to zone-less IP literals up to 45 characters ([events.go:Event.valid](file:///Users/cypark/Documents/project/goauthy/internal/eventlog/events.go#L197-L208)).
- `Store.ListGuarded` and `Store.StreamPageGuarded` evaluate the caller-supplied trusted SQL authorization predicate in the same linearizable snapshot as the data rows via a `UNION ALL` marker row; `MaxPageSize` bounds encoded row size within Rhiza's 16 MiB result budget ([events.go:ListGuarded](file:///Users/cypark/Documents/project/goauthy/internal/eventlog/events.go#L229-L336), [stream.go:StreamPageGuarded](file:///Users/cypark/Documents/project/goauthy/internal/eventlog/stream.go#L22-L42)).
- `Store.VerifyIntegrity` checks the ordered SHA-256 `PrevHash` / `IntegrityHash` chain across `event_log_order` joined with `event_log` ([events.go:VerifyIntegrity](file:///Users/cypark/Documents/project/goauthy/internal/eventlog/events.go#L419-L500)).

## Side Effects
- `Store.ListGuarded`, `Store.VerifyIntegrity`, `Store.StreamPageGuarded`, and `Store.SequenceForID` execute linearizable Rhiza SQL queries.
- `Store.Cleanup` executes a replicated Rhiza `DELETE` of at most `cleanupBatchSize` (1000) rows older than `now - retention` ([cleanup.go:Cleanup](file:///Users/cypark/Documents/project/goauthy/internal/eventlog/cleanup.go#L14-L40)).
