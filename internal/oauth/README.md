# oauth

## Overview
`oauth` implements the Fosite-backed OAuth 2.0 / OIDC authorization server (`Server`) and replicated Rhiza grant/session store (`Store`), including authorization code + PKCE, refresh tokens, client credentials, device authorization grant (RFC 8628), password grant, token exchange (RFC 8693), DPoP (RFC 9449), token introspection/revocation, UserInfo, dynamic client configuration, forward-auth, and upstream session logout.

## Invariants
- `PrincipalClaims` (roles, groups, RBAC revision) and custom claims are resolved dynamically at token/UserInfo boundaries rather than trusted from persisted OAuth session snapshots ([server.go:PrincipalClaims](file:///Users/cypark/Documents/project/goauthy/internal/oauth/server.go#L92-L99)).
- `Store` accumulates Rhiza statements in a context-scoped `transaction` (`BeginTX`..`Commit`) so token issuance, refresh rotation, device claims, account expiry, and token exchange commit atomically with linearizable/CAS guards ([grant_storage.go:transaction](file:///Users/cypark/Documents/project/goauthy/internal/oauth/grant_storage.go#L23-L69)).
- `ForwardAuthHandler` strips incoming `X-Forwarded-*` identity headers before validation, rejects DPoP-bound tokens (`sessionDPoPJKT != ""`), and validates `openid` scope, client existence, and live subject status ([forward_auth.go:ForwardAuthHandler](file:///Users/cypark/Documents/project/goauthy/internal/oauth/forward_auth.go#L10-L80)).

## Side Effects
- Reads and mutates OAuth grant, PKCE, refresh, OIDC session, device, client, and event-log tables in Rhiza.
- Serves OAuth/OIDC HTTP endpoints, signs JWT access/ID tokens via `oidc`, triggers backchannel logout deliveries, and emits metrics/traces/token-issued events.
