# Admin module UI behavior audit

Scope: `catalog.js`, `clients.js`, `collections.js`, `providers.js`, `sessions.js`, `events.js`, `blacklist.js`, and `templates.js`, their focused Node UI tests, plus the corresponding handlers/stores named below. This is a source-and-test audit, not a live browser run. Node UI tests use bounded DOM/API fixtures; they prove the client-side behavior they invoke, not deployment wiring, authorization, or persistence. The Go tests provide separate evidence for the API contracts and storage rules.

| Module and controls | Handler behavior and API/persistence contract | Evidence and remaining limits |
|---|---|---|
| Catalog: list scopes/attributes, New, form fields, Save, Cancel, Delete | Lists scopes from `GET /auth/v1/scopes` and attributes from `GET /auth/v1/users/attr`. Creates with `POST` to those paths; updates/deletes use the encoded entry path with `PUT`/`DELETE`. Attribute JSON defaults are parsed before submit; scope attribute lists are comma-split. Delete asks for confirmation. Success navigates to the list URL; failures leave the form values available. | `catalog.js`, `catalog_ui_test.js`; API contract in `internal/claims/http.go` (`Scopes`, `Scope`, `Attributes`, `Attribute`) and claims tests. UI fixture covers create/update/delete, default JSON, and request-error display. Actual browser history and deployment authorization are unverified. |
| Clients: list, Web/Device presets, form validation, Save, Cancel, Delete, read/rotate/hide secret | Uses `/auth/v1/clients` list/create and per-ID GET/PUT/DELETE; edit and delete send `If-Match` revision. The form checks grant-flow constraints and retains ancillary `backchannel_logout_uri` and `restrict_group_prefix` when updating. Secret read uses POST; rotation uses PUT with `If-Match` and requires a returned revision before allowing further edits. Delete confirms first. Form controls lock during requests; failures retain entered values. | `clients.js`, `clients_ui_test.js`; handlers in `internal/rbac/clients_http.go`, API tests in `clients_http_test.go`, `clients_audience_http_test.go`, and `clients_default_audience_http_test.go`. Node tests verify payload preservation, preset behavior, revision updates, pending lock, conflict preservation, and secret actions. Browser rendering and real authorization are unverified. |
| Collections: list, New/Edit, method selector, provider IDs, metadata-field add/remove/type/options, Save, Cancel, Delete | Uses `GET/POST /auth/v1/auth-collections` and per-ID `GET/PUT/DELETE`. Update/delete carry `If-Match`; create requires ID while update omits it from the body. Field options are parsed as JSON. Client validation limits provider IDs, rejects duplicates, limits API-key collections to one provider, and rejects provider IDs for device flow. Removing existing provider IDs prompts because it revokes connected accounts; delete also confirms. A successful create/update/delete navigates to `/auth/v1/admin/collections`, keeping the URL aligned with the list and browser reload/back. Failed writes keep form data. | `collections.js`, `collections_ui_test.js`; API boundary `internal/rbac/auth_collections_http.go`, persistence/validation `internal/authcollection/store.go`, contract tests `internal/rbac/auth_collections_http_test.go`, `internal/authcollection/store_test.go`, and `internal/apidocs/catalog_auth_collections_test.go`. Node suite covers payloads, cancellation, invalid JSON, conflict retention, pending duplicate submit, and post-write destination. The client does not predict store conflicts caused by existing connections; it displays the server error. Live browser history is unverified. |
| Providers: list, New/Edit, kind selector, OAuth fields, API-key connector JSON, secret, Save, Cancel, Delete | Uses `/auth/v1/saas/providers` list/create and per-ID GET/PUT/DELETE. Edit/delete send `If-Match`; blank replacement secret is omitted. API-key connector JSON must parse before submit. Delete confirms and controls lock during writes. The `oauth2` and `api_key` wire values stay unchanged while their visible labels use localized text. | `providers.js`, `providers_ui_test.js`; handler `internal/rbac/saas_provider_crud_http.go`, store `internal/saas/provider_store.go`, HTTP tests `internal/rbac/saas_provider_crud_http_test.go`. Connector setup prose still needs a locale-catalog entry; this audit's file boundary excludes locale catalogs. |
| Sessions: state/page-size filter, Apply, Next page, revoke session, force logout subject, global logout acknowledgement/confirmation | Lists with `GET /auth/v1/sessions?session_state=…&page_size=…` and uses `X-Continuation-Token` for the next page. Rows is explicitly a requested page size (native integer range 1–65535); helper text explains that the server applies its paging threshold and returns smaller matching result sets in full. Current backend default threshold is 1000 (`DefaultUserListThreshold`; handler startup may override it); below it the response is unpaged/all rows, and at or above it values below the threshold are clamped. Apply validates the integer, writes the filter URL before re-rendering, and resets stale cursors when normalizing malformed URL state. Per-session revoke calls `DELETE /auth/v1/sessions/id/{id}`; subject logout calls `DELETE /auth/v1/sessions/{subject}`; each asks for confirmation. Global logout requires the checkbox and a second confirmation, then calls `DELETE /auth/v1/sessions`; success replaces the page with a completion message. | `sessions.js`, `sessions_ui_test.js`; handlers `internal/rbac/session_list_http.go`, `user_list_http.go`, `session_delete_http.go`, store listing, and tests `session_list_http_test.go`, `session_logout_all_test.go`. Node suite covers requested-size validation, filter serialization, paging, route selection, confirmation and errors. The new explanatory sentence needs a translation-catalog entry to appear in Korean; that catalog is outside this audit’s assigned paths. Real loss of the current browser session and the resulting sign-in are not live-verified. |
| Events: level/type/date/limit filters, Load, Auto-refresh, Next page | Queries `POST /auth/v1/events` with `from`, `until`, `level`, optional `typ`, and `limit`; pagination resubmits the same filters plus `continuation_token` from `X-Continuation-Token`. Auto-refresh repeats the current query every five seconds and stops when unchecked. | `events.js`, `events_ui_test.js`; contract in `internal/rbac/events_http.go`, `internal/eventlog`, `internal/rbac/events_http_test.go`, and event contract tests. Node suite checks query fields, cursor use, filter reset, render and failure display. Stream/refresh timing against a running server is unverified. |
| Blacklist: IP prefix/expiry, Block IP, list, Remove | Lists with `GET /auth/v1/blacklist`; create submits canonical IP text and future Unix-second expiry to `POST`; remove confirms and calls `DELETE /auth/v1/blacklist/{encoded-prefix}`. A 404 list response disables mutation controls and explains that the feature is unavailable. Other errors are shown in the list/status region. | `blacklist.js`, `blacklist_ui_test.js`; contract in `internal/ipblacklist/admin.go`, persistence in `internal/ipblacklist/store.go`, tests in `internal/ipblacklist/admin_test.go` and package tests. Node suite checks date conversion, 404 behavior, create/remove and displayed errors. UI does not locally canonicalize CIDRs; server validation is authoritative. Browser confirmation behavior is unverified. |
| Templates: type selector, language selector, preview iframe | Reads available types/languages from `GET /auth/v1/admin/email-templates`; choosing a type clears the previous iframe and resets language options. Choosing a language builds the read-only preview URL. The iframe has a title and no inline style; sizing is left to the admin stylesheet. | `templates.js`, `templates_ui_test.js`; Go preview handler and embed tests are outside this module's mutation flow. Node suite checks selected URL, type-change clearing, and absence of inline styles. Actual iframe response/CSP behavior is unverified here. |

## Changes and verification

- Fixed the collection list/form route mismatch: after successful create, update, or delete, the browser now navigates to the collections list URL instead of rendering a list while remaining on a detail URL.
- Fixed the same stale-route behavior for catalog saves and deletes.
- Routed collection “Provider IDs”, “API key”, and “Device flow” labels through the existing English/Korean catalog while preserving the underlying field names and enum values.
- Kept template-preview reset-on-type-change and removed inline iframe styling; the focused fixture now models native `appendChild` and checks the generated preview URL.
- Focused Node checks passed: `catalog_ui_test.js`, `clients_ui_test.js`, `collections_ui_test.js`, `providers_ui_test.js`, `sessions_ui_test.js`, `events_ui_test.js`, `blacklist_ui_test.js`, and `templates_ui_test.js`.
- Focused Go checks passed: `go test ./internal/rbac ./internal/authcollection ./internal/ipblacklist ./internal/saas ./internal/eventlog`.

No live browser test was performed. In particular, the report does not claim that mock API responses prove server state changed; that claim is supported only where the matching Go handler/store tests cover the contract.
