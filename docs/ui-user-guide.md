# GoAuthy 기능과 사용 흐름

현재 UI의 기능별 사용법과 실패·취소·복귀 경로를 정리한 안내입니다. 절차 설명과 실행 검증은 다릅니다. 실제 수행 결과와 남은 조건은 [검증 원장](ui-functional-audit.md)을 기준으로 확인하세요.

## 화면으로 들어가기

`/`는 별도 소개 페이지가 아니라 로그인 상태에 따라 이동하는 입구입니다. 로그인 전에는 `/account/login`, 일반 사용자는 `/account`, 관리자는 `/auth/v1/admin/dashboard`로 이동합니다. 계정 화면의 관리자 복귀 링크는 관리자에게만 보입니다. 편집을 취소할 때는 해당 폼의 취소/목록 링크를 사용하세요. 홈은 이전 작업을 기억해 돌아가는 버튼이 아닙니다.

한국어와 English는 화면 오른쪽 위에서 선택합니다. 미저장 입력이 있으면 계속 편집하거나 입력을 버리고 언어를 변경할 수 있습니다. 데스크톱은 왼쪽 내비게이션, 태블릿은 축소된 탐색 영역, 모바일은 펼침 메뉴를 사용합니다. 구간은 CSS 너비 기준 1000px 초과, 541–1000px, 540px 이하입니다.

## 사용 사례별 워크플로우

### 웹 애플리케이션에 로그인 붙이기

관리자가 클라이언트에서 Web 프리셋을 선택하고 실제 callback URI, 허용 플로와 스코프를 설정합니다. 앱에 client ID와 필요한 경우 secret을 설정합니다. 앱에서 로그인을 시작해 GoAuthy 인증 후 원래 앱으로 돌아오는지 확인합니다. 커스텀 클레임이 필요하면 속성 → 스코프 → 클라이언트 허용 범위 순서로 연결하고 발급 토큰에서 확인합니다. 설정 저장만으로 앱 연동이 완료되는 것은 아닙니다.

### 클라이언트의 로그인 화면 꾸미기

관리자는 `Clients` 목록의 **Customize** 또는 클라이언트 편집 화면의 **Login appearance**에서 해당 OIDC 클라이언트의 테마 편집기로 이동합니다. Light/dark 모드별 7개 색 토큰과 버튼 글자색, 공통 모서리 반경을 조정하고 비인증 미리보기에서 확인한 다음 **Save**를 눌러야 클라이언트별 override가 저장됩니다. 다시 불러오면 저장된 값으로 돌아가며, **Reset**은 override를 삭제해 전역 `rauthy` 테마 또는 기본 테마를 사용합니다. 이 편집기는 계정·관리자 화면이나 클라이언트 권한/자격 증명을 바꾸지 않으며, 로고 업로드·삭제, 한·영 로그인 문구, 로고 정렬·카드 너비 편집을 지원합니다. 로고 변경은 별도로 즉시 저장되며 테마 복원으로 삭제되지 않습니다. 자유 HTML·스크립트 편집은 지원하지 않습니다. 로컬 브라우저에서 저장·재조회·복원과 실제 로그인 CSS 반영을 확인했습니다. 자세한 절차는 [통합 설정 안내](ui-guide-integrations.md)를 참조하세요.

### 새 팀원 온보딩

관리자가 역할·그룹 정의를 준비하고 사용자를 생성합니다. 필요한 멤버십을 배정하고 사용자가 첫 비밀번호 설정 이메일을 통해 가입을 마칩니다. 사용자는 로그인 후 계정에서 프로필을 확인하고 패스키를 추가할 수 있습니다. 메일 미수신 시 계정을 중복 생성하지 말고 사용자 목록과 메일 발송 상태를 먼저 확인합니다.

### 외부 SaaS 연결을 서비스에서 사용하기

관리자가 공급자 → 컬렉션을 준비합니다. 사용자는 계정에서 연결 메타데이터를 저장하고 OAuth 인증 또는 API 키 등록을 별도로 완료합니다. 상태가 준비된 뒤 서비스 액세스에서 소비자와 만료를 지정해 동의합니다. 소비자가 실제 작업을 수행하는 것까지 확인해야 전체 연결 성공입니다. 초안, 자격증명 등록, grant는 서로 다른 단계입니다.

### 로그인 장애 또는 의심스러운 접근 조사

이벤트에서 문제 시각과 최소 심각도를 선택해 확인합니다. 사용자 활성 상태·만료·클라이언트 설정을 확인하고 필요한 경우 세션을 조회합니다. 영향을 가장 작게 제한할 수 있는 단위로 세션 종료를 선택합니다. 전체 로그아웃은 현재 관리자까지 종료합니다. 변경 후 기존 자격증명으로 보호된 요청이 거부되는지 확인해야 실제 폐기 효과가 검증됩니다.

### 서비스 자격증명 교체

관리 API 키는 새 이름의 최소 권한 키를 생성하고 소비자에 반영한 뒤 동작을 확인하고 이전 키를 폐기하면 교체 구간을 확보할 수 있습니다. 같은 키의 Rotate는 이전 비밀 값을 즉시 무효화합니다. 외부 API 키 연결의 로컬 취소는 제공자 원본 키를 취소하지 않습니다. 제공자 계정에서 원본 키를 폐기하는 절차는 별도입니다.

### 계정 복구 또는 기기 분실

비밀번호를 잊었으면 복구 메일을 요청하고 유효한 링크에서 새 비밀번호를 설정합니다. 분실한 기기나 의심 세션은 해당 계정의 기기 목록 또는 관리자 세션 화면에서 정확한 대상을 확인합니다. 패스키 삭제, OAuth 세션 취소, 외부 연결 해제는 서로 다른 조치이며 하나를 수행했다고 나머지가 모두 폐기되지는 않습니다.

## 실패하거나 응답이 끊겼을 때

검증 오류는 입력을 수정한 뒤 다시 저장합니다. 충돌이면 최신 레코드를 불러와 변경을 다시 검토합니다. 응답이 끊겼다면 저장 결과가 불명확할 수 있으므로 무조건 재제출하지 말고 목록/상세에서 현재 상태를 확인하세요. 즉시 조회에서 보이지 않아도 원요청이 뒤늦게 완료될 수 있습니다. API 키의 한 번만 표시되는 비밀 값을 잃은 경우 기존 값을 다시 읽을 수 있다고 가정하지 마세요.

전체 API와 UI 경로는 [경로 목록](api-ui-inventory.md), 실제 확인 결과·환경 제한은 [검증 원장](ui-functional-audit.md)에 있습니다. 하드웨어 패스키, 외부 제공자, 실제 메일 수신, 비활성 기능, 다중 노드 동작은 해당 환경의 별도 검증이 필요합니다.
