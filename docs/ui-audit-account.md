# Account UI control audit

Scope: the account page rendered by `internal/account/dashboard.html` and behavior in `dashboard.js`, `connections.js`, `connection_grants.js`, `devices.js`, and `locale.js`. This records static code/API-contract review and deterministic Node tests. No browser, deployed service, or live HTTP session was exercised; the UI suites use mocked DOM and mocked requests.

## Inventory and request paths

All account API calls include same-origin credentials. Mutations attach the dashboard CSRF token. Dynamic provider names, account/client IDs, scopes, user-defined attribute names/descriptions/options, connection metadata, and timestamps are data: the UI displays them as text and does not send them through translation as keys. Literal interface sentences use `t(...)`; `locale_ui_test.js` verifies that every literal key in the four account modules has a Korean catalog entry. Interpolated values are inserted into translated strings and rendered with `textContent`, input values, or native confirmation text, never HTML.

## Verification and limits

The account Node UI suites are deterministic mocked-DOM/request checks, not browser tests and not live API coverage: `dashboard_ui_test.js`, `connections_ui_test.js`, `connection_api_key_ui_test.js`, `connection_oauth2_ui_test.js`, `connection_grants_ui_test.js`, `devices_ui_test.js`, and `locale_ui_test.js`. All seven passed on the current JavaScript candidate. Parent additionally reports live metadata-only connection create/edit/reload/cancel and grant-panel open/close passed; those observations do not establish coverage for provider credentials, OAuth exchanges, grant creation/revocation, or other controls. Go handler/contract tests cited above verify server-side wire shape and policy independently; they do not establish successful integration against a running service. Real keyboard/screen-reader behavior, actual provider authorization/token exchange, WebAuthn hardware/browser behavior, and remaining deployed HTTP behavior are unverified.
